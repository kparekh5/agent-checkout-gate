Agent Checkout Gate

Stripe's post on designing Checkout for AI agents describes tools like select_payment_method and submit_payment that only get revealed to an agent once checkout state actually allows them, so it's never guessing at options that don't apply yet. That part I loved. It also left me wondering about the moment right after submit_payment becomes available: should firing it also require an explicit human OK, not just eligibility? This is a small, self-contained simulation of that one extra gate.

No real payments, no real API calls, no backend. Everything below runs client-side.
